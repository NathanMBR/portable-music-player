# Design tokens

Components use only the semantic colors below, through Tailwind utilities such as `bg-paper`,
`text-ink` or `border-rule`. Tailwind's default palette is turned off (`--color-*: initial` in
`src/index.css`), so a raw color like `bg-blue-500` doesn't exist.

Each token has a light and a dark value. The theme is the `data-theme` attribute on `<html>`, and
the dark values are redefined under `:root[data-theme="dark"]`, so components never use `dark:`
variants.

## Dimming with shade

`ink` turns light in the dark theme, so an overlay made of `ink` would brighten the page instead of
dimming it. Overlays use `shade` with an opacity (the side menu's backdrop is `bg-shade/30`), which
stays dark in both themes.

## Sizes

- **`player`** (`--spacing-player: 4.5rem` in `src/index.css`) is the audio player's height
  (`h-player`). The space kept for it at the bottom of the window (`pb-player`) and the
  notifications' bottom offset use it too while it's open, so nothing hides behind the player.
- **`gutter`** (`--spacing-gutter: 5rem`) is the views' side margins (`px-gutter`). The menu
  button sits in the left one, and the songs' scrollbar sits in the right one, beside the songs.
  The header and the songs both keep the width between the margins, so they end at the same place.
- **`scrollbar`** (`--spacing-scrollbar: 0.375rem`) is the width of every scrollbar, as thin as
  the sliders' track.

## Type

The only typeface is **Archivo Variable**, bundled with the app through
`@fontsource-variable/archivo`. Nothing loads from a CDN, because the player must work offline on
any computer. It has a weight axis and a width axis (`font-stretch`):

- **Titles** are `font-extrabold tracking-tight font-stretch-expanded`: the Songs header
  (`text-4xl`) and the app's name in the side menu (`text-lg`).
- **Song rows** and the audio player's title are `font-stretch-semi-condensed`, so long titles fit
  before they are cut.
- **Playback times** are `tabular-nums`, so the digits don't shift as they count.
- **Body text** keeps the default width.

## Interaction states

- Headless UI exposes component states as data attributes. Style them with `data-hover:`,
  `data-focus:`, `data-checked:` and `data-disabled:`, never with `:hover` or `:focus`.
- **Shared classes:** button looks and states live in `src/components/buttonStyles.ts`, so the
  same situation looks the same in every component. Components own only their geometry (padding,
  size, radius).
- **Looks:** buttons take a `variant`, named by how it looks:
  - `quiet`: a faded label or icon, with `data-hover:bg-rule/60` and full ink on hover. Header,
    song row and audio player buttons.
  - `outlined`: a thin `rule` border around ink, with `data-hover:bg-rule/60`. The menu buttons.
  - `filled`: `pen` with `paper` on it, `data-hover:bg-pen/90`. The one main action on screen,
    like "Try again" or play and pause in the audio player.
- **Focus:** every interactive element shows `data-focus:outline-2 data-focus:outline-offset-2
  data-focus:outline-pen` (`FOCUS_CLASSES`) when reached from the keyboard. Sliders use
  `outline-offset-4`, so the ring clears their thumb. They also hide the ring after a click,
  because Headless UI rings inputs on any focus, like text fields.
- **Active:** whatever is on right now, like a pressed toggle (shuffle, repeat), the playing
  song's button or the current category, shows `pen` on a pen tint (`bg-pen/15 text-pen`,
  `bg-pen/20` on hover; `ACTIVE_CLASSES`). The pen color alone would barely differ from the faded
  icons on the light paper. Toggles also set `aria-pressed`, and the current category
  `aria-current="page"`.
- **Disabled:** a button or slider that can't act right now fades with `data-disabled:opacity-40`
  (`DISABLED_CLASSES`).
- **Cursors:** buttons show a pointer, and disabled buttons and sliders show `not-allowed` (base
  styles in `src/index.css`).
- **Scrollbars:** the app draws every scrollbar like its sliders, with the base styles in
  `src/index.css`: a rounded `rule` track with an `ink-faded` thumb, which turns `ink` on hover
  and `pen` while dragged. The track stops a little above the bottom of the scroll area, so it
  never touches the window's edge or the player. With nothing to scroll, the scrollbar shows
  nothing. Scrollbars have no data attributes, so these states are the one place that uses
  `:hover` and `:active`.
- **Sliders:** `Slider`, behind the volume and the song's position, draws its own track: `pen` up
  to the thumb's center and `rule` after it, with a `pen` thumb that stays inside the track, so at
  the maximum it covers the end. The browser moves that center half a thumb in from each end of
  the track, so the `pen` part ends there too (`fillEnd` in `src/components/sliderFill.ts`) and
  meets the thumb at every value.
- **Motion:** spins and transitions stop for users who prefer reduced motion (`motion-safe:` and
  `motion-reduce:`).
